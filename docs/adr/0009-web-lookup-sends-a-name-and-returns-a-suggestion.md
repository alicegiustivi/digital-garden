# The Garden may look up a name on three public sites, only when the owner asks, and what comes back is a Suggestion from outside

The owner wants the Archivist and the Researcher to look basic facts up on the web (a person's years, a concept's definition, a book's authors) to fill an Object's properties better. Until now the only outside calls were the AI provider and reading a link the owner captured. This is the first time an Object's own content goes to a site that was not asked to be involved, so this records exactly what may leave the Mac, when, and what happens to what comes back. It narrows, and does not contradict, ADR 0002 and ADR 0004.

**What may leave.** Only the **title of one Object** (for example "Ursula K. Le Guin", "Antifragility"), as the search words of one plain https GET request. Never its body, Tags, Connections, other fields or any other Object. The title is the one the Object itself carries: the Garden's fallback title (the start of the body) is never used, so an Object with no title of its own, or whose title is a web address, is not looked up. **Never anything about a Private Object, or one in the Bin**: the same `readable()` gate as the AI, checked when the request is made and again before anything is kept. A Thought is never looked up. The request carries no cookie, key, account, name or address of the owner; its User-Agent names only the app.

**Where.** Three sites, listed in one place (`src/server/web-gate.ts`), which refuses every other address and anything not https: Wikidata and Wikipedia (people, concepts, places, anything with a page) and Open Library (books). All three are free, need no account or key, allow citing, and say so in their terms. Adding a site means changing that list and this ADR. An open web search engine is a possible later step, not this one. A lookup is at most three requests, started by one click; each has a 10 second timeout. Looking things up uses no AI call, so it costs none of the day's free calls and is not held back by the queue.

**When.** The owner presses "Look up on the web" on an Object (the Archivist's side), or turns on "Also look on the web for this question" for one Inquiry (the Researcher's side, off by default, never on by itself). Nothing is automatic. For the Researcher, what is sent is the titles of up to three of the Objects it reads for that question, each still checked as readable; the question's own words never leave. Follow-up questions in an Inquiry keep its switch. Nothing leaves for a question with the switch off.

**Which properties.** A Person: description, years, links. A Concept: definition. A Source that is a book (or has no format yet): authors, published; a Source that is an article, video or other format is not looked up. A type the owner made: only a property the owner has marked "may be looked up" on the Types page, and each says which kind of fact it takes: a short description, a year, or the link to its page. A choice can't be marked. A value the owner wrote is never offered over.

**Origin and Suggestions.** A looked-up value is **Source Origin** (it came from outside, shown ❝ and in italics) and keeps its link, the site's name and the day it was looked up, wherever it is shown or exported. It is never mistaken for the owner's words or for an AI opinion; anything the AI writes around it stays AI Origin. Because a wrong match ("John Smith", two books called "Dune") is the main risk, every value waits as a **Suggestion** with its link and "Approve / Not this". Approving writes it with Source Origin and its link; editing it afterwards makes it the owner's, like any value. "Not this" is remembered for that Object, and the value is not proposed again unless the owner asks. The Garden never guesses between matches: with exactly one item whose name is exactly the title it is used; otherwise (several, or only a near name) the owner is shown the candidates, with a link each, and chooses, or chooses none. Offline, slow, over the site's limit or no match each give a plain sentence and change nothing. A fact applied directly, marked and undoable, for clear single book matches, is possible later once the owner trusts the results; this decision does not make it.

**The Researcher's answer.** With the switch on and at least one passage found, the answer has two parts that the code insists on (an answer that mixes them is not accepted): **From your Garden** and **From the web**, the second citing numbered passages shown beneath with their links. A web claim is never presented as the owner's view; Connections found from the web stay Suggestions; an earlier Inquiry is still never evidence. Titles with no match, or more than one, add a note saying so; a failure never stops the answer, which is then Garden-only with a note.

**Export, Backup.** Export carries a looked-up value with its Origin, link, site and day, and still leaves the Bin out. A Backup copies the database, so the values and links come back with it.

**A decision of the owner: no visible log.** The first plan included a small "what left this Mac" list. The owner chose not to have one. What leaves is instead fixed by the rules above, enforced in one file and proven by tests that read every request made (nothing but the title, never anything Private or in the Bin). If that list is wanted later it is a small addition: every request already passes through the one gate.

**ADR 0002.** "Private means the Garden itself never sends it out" still holds, and is stricter in practice: a Private Object is never looked up. The sentence that Private content "never leaves the Mac except as encrypted backups" still holds for content; what this ADR adds is that the **title of a readable (non-Private) Object** may leave, to the three sites above, when the owner asks. **ADR 0004** ("The Researcher stays Garden-only") now has one exception: the owner's switch, for one Inquiry.
