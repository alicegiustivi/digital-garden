# A type of the owner's own can have a rating and a picture, and its properties can be looked up as a book's author or year

The owner asked for more kinds of property than short text, long text and a choice: a **rating** (stars), a **picture** (a book cover, the same idea as a Person's Portrait), and a way to look up a **name** such as an author. These extend ADR 0008 (owner-made types) and ADR 0009 (web lookup); nothing about the four core types changes.

**Rating.** One to five stars, set and cleared by the owner with a click. It is stored as its number in `field_values` (Origin: owner), so it is searched, exported and backed up like any value. It is an opinion, so **the Archivist is never offered it and never writes it**, and it can't be looked up. It shows as stars on the Object and on its card.

**Picture.** One picture per picture property, added by the owner by choosing a file, dropping one on it or pasting (HEIC works), shrunk and kept in the images folder exactly like a Portrait (`prop-images.ts`, with the same Undo that keeps the previous files until the next change). It lives in its own table (`property_images`), **not** in `field_values`: so it is never searched, never exported as text, never put in a prompt, and **never read or sent to any AI role or outside service**. It shows on the Object and, as the first picture, as the card's cover (a book cover). It is removed with the Object when the Bin is emptied and with its property; Export includes the file and the property's name; Backup copies the images folder; "bring back one thing" brings the picture back. A picture is not found by Search and has no alt text beyond the property's name.

**How they are stored.** A property's `kind` column ('rating', 'image'; migration 0016) marks them; in the database they are a kind of short text, so the existing CHECK on `input` is untouched. The screen sees the kind as the property's input. Neither can be the property shown under the title.

**Names.** The owner wanted names such as an author looked up. Rather than a new kind, a **short or long text** property can now be marked "A book's author" or "A book's first year", next to the three kinds ADR 0009 made. A type with such a property is looked up as a book on Open Library (one of the three sites ADR 0009 allows), by its title only; the author's name and the year wait as Suggestions with their link, like every looked-up value, and a value the owner wrote is never offered over. The name stays plain text: a link to a Person Object (an author with their own page) was offered and the owner chose not to have it for now. These two kinds live in their own column (`lookup_book`) because SQLite can't widen the earlier CHECK.

**Not in this decision.** A picture found on the web (a cover from Open Library) is not offered: it raises rights questions and sends more than a title. Dates and links as property kinds are still a later question.
