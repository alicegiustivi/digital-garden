# The Archivist describes People and Concepts from the Garden's own Sources

The Archivist now fills in a **Person** (description, years lived, links) and a **Concept** (its definition, the lead field shown under the title). It is the same kind of AI Contribution as a Source's title or authors: applied directly, marked ✦ with role, model and date, undone in one click (ADR 0001, 0003).

**Only from the Garden.** The model is shown the passages of the connected Sources' extracts that mention the subject (its name, surname parts or aliases; for a Source the Person wrote, its opening) and is told it knows nothing else. A year must appear in those passages and a link must appear word for word, or code drops it. This keeps the Garden-only rule for the AI (a question that needs outside facts stays a gap) and means a Person with no Source text yet is simply not described. Private Sources and Objects are never read; Thoughts are not used as evidence, so the description is never built on the owner's own opinions.

**Never the owner's words.** An owner-written value is never touched. An earlier AI value is replaced by a newer one, so a description can grow as Sources are connected, and Undo restores what was there before.

**When.** One request, when a Person or Concept is made by approving a Suggestion (including a Concept suggested from a recurring Tag, ADR 0005), when the owner turns a Tag into a Concept, or when the owner presses "Ask the Archivist" on it. No request is made when every field is already the owner's or no connected Source has words about it.

**Fix (regression):** the first version sent a Person or Concept only to the description step, so they stopped getting Tags and Connections. They now get the full treatment: the description request also returns 2–4 specific Tags; a Source that lists the Person among its authors is connected "authored by" with no request (a plain name match); and a second request judges Connections against what the candidates say. For a Person or Concept the candidates start with the Sources whose own text names it (found on this Mac, even when not yet connected), each shown as the passage that names it rather than its opening.

**Review fixes (same change):** (1) a Concept made from a Tag is named with spaces ("loss aversion", not "loss-aversion"), and a name is compared the way a person reads it, so a Tag no longer produces a second Concept next to one the owner already has, and the Sources that write it with spaces are found; (2) a single-word subject also matches its stem ("reflection" finds "reflecting"), and a Source the owner connected to a Concept but that never names it contributes its opening, marked as such; (3) vague Tags written with several words ("web page", "reading list") are now dropped as saved; (4) a daily limit or refused key during the Connections request makes the job wait and run again, instead of finishing silently without Connections; (5) the model's JSON is found even when it writes braces before the answer; (6) text copied from outside (a captured article, the Sources' passages) is fenced in `<extract>` tags and every prompt that shows it says never to follow instructions found inside, so a captured page cannot steer the Archivist or the Researcher.

**Tags no longer depend on Source text:** the description request also returned the Tags, so a Person whose Sources had no text to read (book cards), or who had no Source yet, never got Tags. When there is no passage to describe from (or the owner already filled the description), the Archivist now sends a Tags-only request built from what the Garden holds: the description or definition already there (marked by whose words it is), the owner's words on its page, and the title, author and Tags of each connected Source (never a Private one). Nothing else is written from it, whatever the model returns, and with only a name to go on no request is made. A Source that lists a Person among its authors is now connected before that request, so it can be used.

**Finding the Sources for a Concept (fix):** a Concept named by several words ("Fear of failure") was only matched by the exact phrase, so a Source that says "afraid of failing" never reached the model, which was instead shown the 15 most recently changed Objects. Now each content word of a Concept's name and a rough stem of it ("fail" for "failure") also match, in a Source's text, its summary and its title, with the full name counting more; a Person or Concept is shown up to 30 candidates (`maxCandidatesEntity`); and each candidate is shown with its summary (written by the Archivist) as well as the start of its text, so the model can judge a Connection by what the Source is about. Stems are used only for Concepts, so a surname never finds a first name.
