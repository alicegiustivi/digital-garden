# The Garden runs only on the owner's Mac; the phone only captures

The Garden is a local web app on the owner's Mac, reachable only from that Mac, with its database and images in a `Garden` folder outside the code repository. The phone's only role is Capture: the owner messages a Telegram bot that accepts only their account, its Google Apps Script drops each capture into a Google Drive folder that syncs to the Mac, and the Garden picks it up and deletes the file. Backups go to Google Drive daily, encrypted with a password only the owner knows.

We chose this over hosting the Garden on Cloudflare (Workers, D1, R2), which the hosting research recommended. Hosting needed a credit card on file for image storage with no hard spending cap, a login, a second host or workaround for link extraction under the 10 ms CPU limit, and a 500 MB database cap. Running locally removes all four, and Private content never leaves the Mac except as encrypted backups. The cost: the Garden can't be browsed from the phone, the Archivist works only while the Mac is on, and phone captures pass through Telegram and Google before they arrive, so Private now means "the Garden itself never sends it out" rather than "it never touched an outside service". Moving to a hosted Garden later means porting storage, adding a login, and revisiting the image-storage card question.

The server also refuses any request whose Host or Origin is not this Mac (127.0.0.1, localhost, [::1]), so a web page open in the owner's browser cannot talk to the Garden by DNS rebinding or a cross-site request (final pass, #99).

**Later (ADR 0009, issue #108):** the Garden can look an Object's title up on Wikipedia, Wikidata or Open Library, only when the owner asks. Private Objects and the Bin are never looked up, and nothing but one title leaves.
